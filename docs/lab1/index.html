Lab 1: HMWK 1 — Public-key cryptography (simple)

The same homework in a minimal version: compute G, 2G, …, kG, print the toy public key, then explore the statistics of the results.

Private key → public key (simple version)

Elliptic-curve scalar multiplication is a one-way function: computing the public key Q = kG from the private key k is easy, but finding k from Q is hard (the ECDLP). Ethereum uses the curve secp256k1; here we use a tiny toy curve.

  • Curve: y² = x³ + 7 (mod 17)
  • Base point: G = (1, 5)
  • Public key: Q = kG = G + G + … + G (k times)

Discussion

  
What the numbers show

  
    
    
  • Coordinates are not uniform. Only x values for which x³ + 7 is a square
      mod 17 can occur, and with G = (1, 5) only 4 of the 17 values appear at all. The y values come in pairs
      y and 17 − y. The χ² test rejects uniformity.
    • 
    
  • Points are uniform over the group. When k runs over whole cycles, every
      point of the subgroup generated by G appears equally often, because k ↦ kG is a bijection on 1…n − 1. With all base points pooled, subgroups of different
      sizes (n = 3, 6, 9, 18) are mixed, so the pooled counts are no longer uniform.
    • 
    
  • Bits are biased. Numbers below 17 rarely have bit 4 set, so the bits of the
      coordinates are not fair coins. This comes from p not being a power of 2, not from a weakness.
    • 
    
  • No linear correlation, but a lot of structure. r(k, x) and r(k, y) are close to 0,
      yet kG and (n − k)G always share x, and (k + j)G = kG + jG holds every time.
    • 
    
  • The "avalanche" is accidental. Flipping one bit of k changes many output bits,
      but only because the group is tiny and kG jumps around. Nothing in the design aims for 50%,
      unlike SHA-256.
    • 
  


  
Meaningful for an elliptic-curve one-way function

  
    
    
  • Deterministic and easy forward: the same k always gives the same Q, and computing it is fast.
    • 
    
  • Hard to invert (ECDLP): this needs a huge group (n ≈ 2²⁵⁶ on secp256k1).
      No statistic on a toy curve can measure it, because here everything can be brute-forced.
    • 
    
  • Uniform over the group: for a uniformly random k, Q is a uniformly random point of
      the group. This is the distribution property that matters, not uniformity of bit strings.
    • 
    
  • Algebraic structure is a feature: (a + b)G = aG + bG is exactly what makes digital
      signatures (ECDSA) and key agreement (ECDH) possible. The ±Q symmetry is known and harmless.
    • 
  


  
Specific to cryptographic hash functions

  
    
    
  • Avalanche effect: one changed input bit flips about 50% of the output bits.
    • 
    
  • Uniform, independent output bits that look like a random bit string.
    • 
    
  • No exploitable relations: H(a + b) has nothing to do with H(a) and H(b).
      A hash must not have the structure that the curve needs.
    • 
    
  • Collision resistance for inputs of any length, mapped to a fixed-length output.
      kG has no collisions at all for 1 ≤ k ≤ n − 1, because it is a bijection.
    • 
  

  

    Ethereum uses both: the curve turns the private key into a public key with useful structure
    (for signatures), and the Keccak-256 hash turns the public key into a random-looking 20-byte
    address. Keep in mind that statistical tests only measure appearance. Passing them does not make a
    function one-way, and failing them (biased bits) does not make it insecure.
