Lab 3: HMWK 3 — Toy curve encryption vs the Caesar cipher

EC-ElGamal on the toy secp256k1-style curve of Lab 1: encrypt and decrypt a message, compare it with the Caesar cipher, then break Caesar with letter statistics.

1. Elliptic-curve encryption (EC-ElGamal)

We use the toy curve of Lab 1, y² = x³ + 7 (mod 17) with G = (1, 5).

  • Private key d: secret integer of the receiver (Bob).
  • Public key Q = dG: published by Bob; computing d from it is the ECDLP.
  • Ephemeral key r: fresh random integer chosen by the sender (Alice) for each block.
  1. Encoding. The text is split into 4-bit values m, each mapped to one of 16 fixed curve points M.
  2. Encryption (uses Q only). Send C1 = rG and C2 = M + rQ.
  3. Decryption (uses d). Since dC1 = d(rG) = r(dG) = rQ, we get M = C2 − dC1.

2. Caesar cipher

Each letter is shifted by a secret k: encryption c = (m + k) mod 26, decryption m = (c − k) mod 26. The same message is used.

  • Caesar only relabels the alphabet, so entropy, top share and coincidence equal those of the plaintext. The most frequent letter reveals k (frequency analysis).
  • ElGamal adds a random mask: C1 is independent of the message and C2 is spread over many points, so equal plaintext blocks give different ciphertexts. In the toy the mask takes only 9 values, so the spread is not fully uniform.

Conclusion

Caesar is a keyed substitution with a 25-key space and no statistical protection. EC-ElGamal needs two keys and a hard problem, randomises every block and hides the plaintext statistics; on secp256k1 its key space is also out of reach for brute force.

4. Statistical cryptanalysis of the Caesar cipher

Algorithm. Letter frequencies pi are measured on a reference English corpus (about 1400 letters, with add-one smoothing). For a ciphertext of N letters and each candidate key k = 0, …, 25:

  1. decrypt with k and count the letters, obtaining the observed counts Oi;
  2. compute χ²(k) = Σ (Oi − N·pi)² / (N·pi);
  3. return the k with the smallest χ².

Only 26 candidates are tested, but the statistic does the work: the true key is the shift that makes the whole distribution look English, not just the letter E.

Discussion

  • Effectiveness. The success rate rises quickly with length: it is already very high at 20 letters and essentially 100% from 50 letters, because the observed distribution converges to the language distribution as N grows.
  • Short texts. With 5–10 letters the sample is too small to show the language profile, so wrong keys can score better (about half the 5-letter ciphertexts fail).
  • Limitations. The attack needs the language to be known and a reference corpus of that language. It assumes a single fixed shift, so it fails on polyalphabetic ciphers such as Vigenère, and on text whose letters are unusual (a lipogram, a table of numbers, a different language).
  • Why it works at all. Caesar preserves the letter distribution up to a rotation (Section 3), so a distribution-based statistic is enough. A cipher that hides the distribution, like the ElGamal blocks above, cannot be attacked this way.
  • Remark. The test windows overlap, since the test corpus is short (about 760 letters), so the long-length results are less independent than they look.
